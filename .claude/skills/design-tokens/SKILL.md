# Design Tokens

Переводит решённую айдентику (цвет, типографику, ритм) в токены, на которые может ссылаться код — не изобретает саму айдентику. Если архетип, палитра-концепция и шрифтовая пара ещё не выбраны — это не сюда, это к смысловой части работы (архетип/композиция/тип), а design-tokens уже кодифицирует то, что решено.

## Порядок работы

1. **Прочитать `references/dtcg-format.md`** — там формат DTCG, три уровня (primitive/semantic/component), рекомендованные шкалы отступов и типографики, и метод генерации OKLCH-палитры с проверенным контрастом. Не пропускай, если это первый токен-файл в проекте — там объясняется, почему нельзя смешивать уровни.
2. **Посмотреть, что уже есть** в `tokens/` в корне проекта (если директория существует) — новые токены должны продолжать существующую структуру, а не вводить параллельную.
3. **Сгенерировать/расширить токены**, разделяя три уровня явно:
   - primitive — сырые значения, не используются в коде напрямую
   - semantic — алиасы по назначению (`color.action.primary`, `space.gap.default`)
   - component — алиасы под конкретный компонент, если он уже специфицирован
   - для новой цветовой палитры — 11 OKLCH-шейдов и обязательная проверка контраста скриптом (шаг 4), не на глаз
4. **Проверить контраст** для любого нового цвета, который пойдёт в текст или UI-элемент:
   ```bash
   python3 .claude/skills/design-tokens/scripts/contrast.py "<hex>" "#ffffff"
   ```
   Порог: ≥4.5:1 для текстового оттенка, ≥3:1 для UI/иконок. Не публикуй оттенок, который не прошёл порог — сдвинь lightness и перепроверь.
5. **Валидировать файлы**:
   ```bash
   python3 .claude/skills/design-tokens/scripts/validate_tokens.py
   ```
   Ловит невалидный JSON и незарезолвленные алиасы. Запускай после каждого изменения, не только в конце.

## Формат вывода

DTCG JSON, с `$description` на каждом токене (что это и откуда значение), только через ссылки между уровнями — без хардкода значений там, где должен быть алиас на семантику.

## Что это не заменяет

Не заменяет ревью айдентики глазами (это про технику, не про вкус) и не заменяет полный accessibility-аудит компонента — контраст здесь проверяется как часть генерации токена, а не как замена скилла `a11y-audit` для готового интерфейса.
