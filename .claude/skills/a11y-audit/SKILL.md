# Accessibility Audit

Проверка по WCAG 2.2, а не по интуиции. Правило: **никогда не называй коэффициент контраста, который не измерил скриптом** — «выглядит достаточно контрастным» не проходит как ответ.

## Обязательный набор P0 (без исключений)

- клавиатурная навигация — всё интерактивное достижимо и активируется с клавиатуры
- видимый фокус — индикатор фокуса с контрастом ≥3:1 к фону
- доступное имя/роль/состояние для скринридера у каждого интерактивного элемента
- контраст текста ≥4.5:1 (обычный) / ≥3:1 (крупный, ≥24px или ≥19px bold)
- контраст UI-элементов (границы кнопок, иконки, индикаторы состояния) ≥3:1
- размер интерактивной цели ≥24×24px (WCAG 2.5.8)
- смысл никогда не передаётся только цветом (ошибка — не только красным, но и текстом/иконкой)

## Дополнения WCAG 2.2, которые часто забывают

- **2.4.11 Focus Not Obscured** — фокус не должен перекрываться sticky-хедером/оверлеем
- **2.5.8 Target Size** — минимум 24×24px, если нет оправданной причины меньше (инлайновая ссылка в тексте — исключение)
- **3.3.8 Accessible Authentication** — если есть форма логина/капча, не требовать когнитивный тест без альтернативы

## Контраст — измерять, не оценивать

Для любой пары цвет-текст/цвет-фон:

```bash
python3 .claude/skills/a11y-audit/scripts/contrast.py "<fg-hex>" "<bg-hex>"
```

Скрипт печатает точный коэффициент и pass/fail по AA/AAA для обычного текста, крупного текста и UI-элементов. Прогони его для каждой заявленной пары в макете/токенах — не только для «основной» комбинации текста, отдельно для состояний hover/disabled, если они меняют цвет.

## Формат ответа

Таблица находок:

| Критерий WCAG | Серьёзность | Что не проходит | Фикс |
|---|---|---|---|
| 1.4.3 | P0 | текст `#8a8a8a` на белом — 2.3:1, нужно 4.5:1 | сдвинуть до `#5c5c5c` (замерено: 4.6:1) |

Явно подтверждай и то, что прошло проверку, не только находки — иначе непонятно, что реально было проверено, а что пропущено. Доступность не размен на эстетику: если найденный фикс "портит" визуально дизайн — это сигнал пересмотреть дизайн, не пропускать P0-находку.

## Чего этот скилл не делает (пока)

Оригинальная версия этого инструмента (в репозитории plugin87/ux-ui-agent-skills) умеет гонять реальный рендер страницы в браузере через Node-скрипты (`measure_render.mjs`, `verify_states.mjs`) — измерять контраст и состояния (`hover`/`focus`) на фактически отрисованной странице, а не на заявленных hex-парах. Здесь этого нет — если нужно проверять уже собранную HTML/React-страницу через headless-браузер (Playwright уже есть в этом окружении), это отдельная задача на добавление, скажи и соберу.
